# Разбор backlog (адаптация `triage-issue` / `triage-issues`)

Скиллы-оркестранты: `triage-issues` (проход по открытым issue) и `triage-issue`
(разбор одного issue) из `tomzx/agents`. Канон состояний — скилл `triage`
(mattpocock/skills) и `docs/agents/triage-labels.md`; настоящий файл описывает
только адаптацию и приоритетен над текстом скиллов tomzx.

## Роли в пайплайне

1. `triage-issues` / `triage-issue` — **обогащение**: собрать контекст,
   классифицировать тип, проверить дубликаты, запросить недостающее.
2. `triage` — **решение**: перевести issue по state machine
   (`needs-triage` → `needs-info` / `ready-for-agent` / `ready-for-human` / `wontfix`)
   и написать agent brief для `ready-for-agent`.

Оркестрант никогда не выставляет финальное состояние в обход `triage`.

## Что из таксономии tomzx действует в SystemDeck

| Измерение tomzx | Статус в SystemDeck |
| --- | --- |
| `type`: `bug`, `feature`, `question`, `chore`, `documentation`, `security` | Действует; маппинг на наши категории: `bug` → `bug`, `feature` → `enhancement`, остальное — без категорийной метки, только текстом в summary |
| `needs-info`, `duplicate`, `invalid` | Действуют (метки существуют) |
| `has-repro` / `needs-repro`, `regression`, `data-loss`, `stale` | Не действуют — таких меток нет; фиксировать словами в summary, метки не создавать |
| `area:*`, `component:*`, `platform:*`, `api:*`, `perf:*`, `urgency`, `importance`, `priority:*` | Не действуют — таких меток нет; discovery (`gh label list`) это подтвердит — пропустить измерение |
| Issue Types / Priority field (GraphQL) | Не использовать — в репозитории не заведены |
| `ghx` | Не использовать — в проекте нет `ghx`; везде эквивалент `gh` |

## Запрет автосоздания меток

Шаг Area Label Creation из `triage-issue` (`gh label create "area:<name>"`)
в SystemDeck запрещён: новые метки — только явным решением мейнтейнера.
Если измерению некуда лечь — писать в summary строкой вида
`предлагается метка area:storage — не создана, нет таксономии`.

## Дубликаты и комментарии

- Поиск дубликатов — по открытым и закрытым (`gh issue list --state all`),
  порог — минимум 2 совпадающих сигнала из скилла.
- Найденный дубликат: метка `duplicate` + комментарий со ссылкой на оригинал.
- Недостаточно данных: метка `needs-info` + конкретный вопрос
  (что ожидалось / что произошло / шаги воспроизведения).
- Каждый комментарий триажа начинается с дисклеймера `triage`:
  `> *This was generated by AI during triage.*`
- Футеры атрибуции `github-post-attribution` из tomzx в проекте отсутствуют —
  не добавлять, вместо этого в конце тел PR/комментариев агента указывать строку
  `Skills: <id1, id2, …>` по `AGENTS.md`.

## Техническая часть GitHub

Отдельный GitHub-скилл (в т.ч. официальный от OpenAI) не устанавливается:
техническую часть уже закрывает `gh` CLI по `docs/agents/issue-tracker.md`
(create/read/list/comment/label/close). Скиллы выше описывают только методику.
