# Модель безопасности Cleaner — scan → preview → selection → delete → report

EPIC 5 (Cleaner). Первая деструктивная зона SystemDeck: очистка после того, как Storage Analyzer (EPIC 4, ADR 0013) уже объяснил занятость диска. Решили: удаление идёт только по явному выбору пользователя из готовых кандидатов; каждое правило очистки имеет узкий allow-список путей/паттернов; всё вне правил мусором не считается никогда; результат — per-item отчёт без скрытия частичных неуспехов. EPIC 4 остаётся строго read-only гранью: Scan Result не является источником кандидатов на удаление.

## Considered Options

- **Blind-очистка «одним кликом»**: отклонено — нарушает принцип продукта «мониторинг и объяснение до деструктивных действий» (roadmap #1) и Constraints эпика #22; необратимое удаление без preview недопустимо.
- **Кандидаты из Scan Result EPIC 4**: отклонено — результат lean без per-file дерева (ADR 0013), быстро протухает; движок кандидатов Cleaner строится отдельно, с собственными allow-правилами и свежим обходом только разрешённых корней.
- **Удаление из Renderer напрямую**: отклонено — нарушает границы ADR 0002 (Privileged API только Main/Preload); удаление выполняет только Main по invoke-каналу после явного подтверждения, Renderer получает кандидаты и отчёт готовыми.
- **Deny-список вместо allow-списка**: отклонено — deny-модель пропускает неизвестные пути; каждое правило обязано задать узкий allow-корень/паттерн, всё остальное по умолчанию защищено (прецедент — хардкод-список Protected Process, ADR 0011).
- **Сводный отчёт «успешно/нет»**: отклонено — скрывает частичные результаты; отчёт идёт per-item (путь, байты, ok/ошибка с кодом), итоговая сводка считается из per-item записей.

## Consequences

- Новые invoke-каналы (`cleaner:*`) требуют контрактов в Shared (compile-time assertions), кодов ошибок (`CLEAN_*`) и бампа `SHARED_CONTRACT_VERSION` — в детских issues движка и протокола.
- Классификация категорий и Protected Paths — хардкод-таблицы в Main (прецедент ADR 0011/0013); Renderer классификацию не выполняет.
- Политика Reparse Point и Inaccessible Directory из ADR 0013 действует и здесь: ссылки не обходятся, недоступное помечается и не абортит операцию.
- Ошибки удаления сериализуются как IPC Error без stack/cause; полный текст — только в Application Log Main (Log Redaction, CONTEXT.md).
- Термины Candidate/Protected Paths/Cleanup Report фиксируются в CONTEXT.md при реализации движка.
