# Скан хранилища — push-протокол прогресса/отмены и lean-результат

EPIC 4 (Storage Analyzer). Первая долгая операция в SystemDeck: read-only обход фиксированного тома с агрегацией каталогов, top-100 файлов и сводкой по типам, с прогрессом и отменой. Решили: скан идёт один за раз и целиком в Main; прогресс — push-канал `systemdeck:push:storage:scan:progress` (throttle ~100 мс), терминальное событие того же канала несёт готовый Scan Result (`complete | cancelled | failed`); управление — invoke `storage:scan:start` / `storage:scan:cancel`, кэш читается через `storage:scan:get`. Результат — lean: агрегированное дерево каталогов (Directory Node) + Largest Files + сводка по File Type Category, без per-file дерева; кэшируется in-memory на сессию на том.

## Considered Options

- **Poll вместо push-прогресса**: Renderer сам опрашивает состояние — дублирует устоявшийся push-паттерн (ADR 0008) и добавляет гонки между опросами; push остаётся единственным механизмом долгих потоков.
- **Полное per-file дерево в результате**: на системном диске это сотни МБ в памяти, и данные протухают мгновенно; всё, что нужно EPIC 4 (агрегаты, top-100, типы), считается в один проход. Файловая детальность для preview/selection — зона EPIC 5 (Cleaner), walker проектируется с готовностью к расширению, но файлы в EPIC 4 не удерживаются.
- **Обход Reparse Point с loop-guard**: заход внутрь корня даёт непредсказуемое время и границы; в v1 ссылки не обходятся вообще (цикла быть не может), размер цели не считается.
- **Access-denied как фатальная ошибка**: запрет обрывал бы весь скан; вместо этого узел помечается Inaccessible Directory и обход продолжается, счётчик недоступных папок в результате.
- **Кэш на диск между запусками**: данные файловой системы устаревают быстро, поверхность хранения не даёт пользы; кэш только in-memory на сессию, единственная инвалидация — явный rescan.

## Consequences

- Новые каналы требуют контрактов (compile-time assertions), кодов ошибок `SCAN_ALREADY_ACTIVE`/`SCAN_NOT_ACTIVE` и бампа `SHARED_CONTRACT_VERSION`.
- Классификация файлов по категориям — хардкод-таблица расширений в Main (прецедент — список Protected Process, ADR 0011); Renderer получает готовые строки.
- Серверная политика Reparse Point и Inaccessible Directory — термины в `CONTEXT.md`, чтобы визуализация и EPIC 5 трактовали недоступное/не собранное единообразно.
- Scan Result — грань для EPIC 5 (Cleaner): lean-результат уже резервирует место для расширения, но сами файлы EPIC 4 не хранит.
