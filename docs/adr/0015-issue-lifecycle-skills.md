# Issue-скиллы: создание, разбор backlog и триаж

Контекст — issue в `andr-235/systemdeck` велись вручную: структура тел не зафиксирована,
канонические метки `needs-triage`/`needs-info` отсутствовали в трекере, таксономия разбора
backlog не определена. Решили: взять структуру из `n8n:create-issue` (Goal→Background→Scope→Acceptance→Out of scope,
для багов Description→Expected→Actual→Steps→Context), ведение после создания — из `triage`
(mattpocock/skills, state machine needs-triage/needs-info/ready-for-agent/ready-for-human/wontfix),
массовый разбор — из `triage-issue`/`triage-issues` (tomzx/agents); все через `npx skills add`
с записями в `skills-lock.json`, адаптации — в `docs/agents/create-issue.md` и `docs/agents/backlog-triage.md`.

## Considered Options

- Сырой `n8n:create-issue` без адаптации — сохраняет Linear-ветку (MCP, команды, приоритеты,
  Notion-lookup) и n8n-специфику (GitHub только для багов, запрет ручных меток); отвергнут —
  в SystemDeck только GitHub через `gh`, новый issue стартует с `needs-triage` (инверсия гардрэйла n8n).
- Полная таксономия tomzx (`area:*`/`platform:*`/`api:*`, urgency/importance, Issue Types,
  Priority field, `ghx`, автосоздание меток) — отвергнута: таких меток/полей в трекере нет,
  автосоздание меток запрещено (расползание лейблов), `ghx` и attribution-футеры отсутствуют;
  от tomzx берётся только методика обогащения + поиск дубликатов.
- Отдельный GitHub-скилл (в т.ч. официальный от OpenAI) — отвергнут: техническую часть
  (create/read/list/comment/label/close) полностью закрывает `gh` CLI
  (`docs/agents/issue-tracker.md`); скиллы описывают методику, а не транспорт.
- Ручное копирование SKILL.md без `skills-lock.json` — отвергнуто: ломает воспроизводимость
  (`experimental_install`) и аудит хешей (см. ADR 0014).

## Consequences

- Новые issue: структура по типу из `docs/agents/create-issue.md`, стартовая метка `needs-triage`,
  превью до создания, дубликаты проверяются поиском до создания.
- Backlog: `triage-issues` (пачка) → `triage-issue` (штучно) как обогащение, финальное состояние
  выставляет только `triage`; каждый комментарий триажа начинается с
  `> *This was generated by AI during triage.*`, в PR/комментариях агента — строка
  `Skills: <id1, id2, …>`.
- Созданы недостающие метки `needs-triage`, `needs-info`; остальные измерения без меток
  фиксируются текстом в summary, новые метки — только решением мейнтейнера.
- Риск — дрейф апстримов (`n8n-io/n8n`, `tomzx/agents`, `mattpocock/skills`); митигация — пин хеша
  в `skills-lock.json` + периодический `npx skills update` с перепроверкой адаптаций.
